# G6a — Public site, client portal, dashboards, advanced search, reports & export (staging spec)

Source: execution plan §G6 «المرحلة السابعة: البوابة والتقارير والمراسلات الذكية», **steps ١–٥ only**. Goal: serve the client and the management with what each one may see, and nothing more. Exit criteria for G6a: «لا يرى العميل ملفات غيره حتى بروابط مباشرة» (step ٢), «البيانات المالية الرسمية تُقرأ من مصدرها المعتمد» (step ٣), «فلترة النتائج وفق المؤسسة والعضوية» (step ٤), «تصدير متطابق مع الفلاتر والإجماليات الظاهرة … يخضع لنفس الأذونات» (step ٥).
Read first: `docs/online/ARCHITECTURE.md`, `docs/online/G5_SPEC.md`, `docs/online/G4_SPEC.md`, `docs/online/G3_SPEC.md` (each with its "As built"), `docs/online/G5_REPORT_AR.md`. Staging only.

**G6a is read-side only.** It adds readers (search, dashboards, reports, the portal invoice reader) and one append-only log (`report_exports`). It changes no operational, cost, billing or sync logic, adds no column to an existing table (the 0700 / G3 / G5 column grants are fail-closed: a new column on `transactions`, `clients`, `service_requests` or `transport_trips` would be hidden until re-granted — so none is added), and never contacts Daftra.

**Messaging (plan steps ٦–٢٥) is G6b, not built here.** Reserved now so G6b needs no renames: NAV group id `comms` (i18n key `msg.nav_group`), i18n namespace `msg`, module folder `assets/js/msg/`, routes `#inbox`, `#channels`, `#contacts`, migration slot `20261107000100_g6b_messaging.sql`. The existing `#messages` view (contact-form inbox) is unchanged. Nothing of this is created in G6a.

## Binding rules (apply to every item below)
- One migration: `supabase/migrations/20261106000100_g6a_portal_reports.sql`. Re-runnable (IF NOT EXISTS / OR REPLACE / DROP … IF EXISTS), applies on the LIVE staging DB that already holds G2 + G3 + G4 + G5 data.
- Every `SECURITY DEFINER` function: `SET search_path = ''`, auth check first (`IF auth.uid() IS NULL THEN PERFORM app.fail('MRS_AUTH_REQUIRED'); END IF;`), errors only via `app.fail('MRS_*', detail)`, `REVOKE ALL ON FUNCTION … FROM PUBLIC, anon, authenticated`, then `GRANT EXECUTE … TO authenticated`. `app.*` helpers stay revoked from everyone (none is used by an RLS policy, so none is granted). Prefer `SECURITY INVOKER` / plain RLS where it is enough (the portal keeps reading through RLS; only `portal_invoices` is a definer function, because `billing_intents` has no client policy, G5-6).
- Every reader filters **inside the SQL** by (a) org membership (`p_org` + `app.is_staff(p_org)` / `app.has_role` / `app.fin_org_read`), (b) **branch scope per row** (`app.has_branch_role(t.org_id, t.branch_id, <roles>)` on the parent transaction), (c) role: finance figures only where the caller has `app.fin_read_roles()` at that row's branch, trip cost / sell only with `app.trip_finance_roles()` at that branch, clients only their own `client_id` (`app.my_client_ids()`). The UI never filters for security.
- Filters: `p_filters jsonb`, keys checked with `app.only_keys`, parsed with the existing `app.puuid / app.pdate / app.ptext / app.pnum / app.pbool`; status codes checked with `app.is_code(domain, code)`. Free text ≤ 80 chars, LIKE metacharacters `\ % _` escaped (`app.rpt_like(text)` → `'%' || escaped || '%'`).
- Dates: every date filter and every "today" is **Asia/Riyadh** (`(ts AT TIME ZONE 'Asia/Riyadh')::date`, `app.rpt_today()`), same as `margin_report`. A range with `from > to` → `MRS_INVALID 'date_range'`; a range wider than 1096 days → `MRS_INVALID 'date_range'`.
- Pagination: `limit` (search ≤ 100, default 25; reports ≤ 500, default 100), `offset` (≤ 1 000 000). Every paged reader returns `total` and `totals` computed over the **whole filtered set**, never only the page, plus a `fingerprint` (see §5.3).
- No writes except `log_report_export`. No DELETE anywhere. No new `transaction_events` type.
- Money is returned as JSON numbers with 2 decimals (`round(x, 2)`), counts as integers. Currencies never mixed: every money total is keyed by currency (`totals.by_currency`).

### 2.2 `portal_invoices(p_tx uuid DEFAULT NULL)` → jsonb
`SECURITY DEFINER`. Auth first. **Ownership = the invoice's own bill-to client** (`billing_intents.client_id ∈ app.my_client_ids()`, frozen by G5), never the transaction's current `client_id` (review fix). `p_tx` given and neither a transaction whose `client_id ∈ app.my_client_ids()` nor one with an issued intent billed to the caller → `MRS_NOT_FOUND 'transaction'` (same answer for "exists in another org" and "does not exist"). Returns `{items:[…], count}` ordered by `issued_at DESC, id`, at most 200:
`{id, transaction_id, transaction_ref, daftra_number, issued_at, currency, net, vat, total, payment_status, paid_amount, remote_state}` where `net/vat/total` = `remote_net/remote_vat/remote_total`, and `remote_state = 'cancelled'` when an `issued_cancelled` review item of that intent is still `open`, else `'issued'`. Only `status='issued'` intents. A staff user without client links gets `{items:[], count:0}`.

### 2.3 "Never others' files, even with direct links" — proof obligations (tests, §8)
As client B (other client of the same org) and client C (other org): reading A's transaction / containers / documents / `transaction_events` by **id** returns 0 rows; `storage.objects` row for A's document path → 0 rows (so no signed URL can be minted: the storage read policy evaluates `documents` RLS); A's **internal** document (`visibility='internal'`) and a **voided** client document → 0 rows even for A; `portal_invoices(<A's tx>)` → `MRS_NOT_FOUND`; every staff reader / dashboard / report RPC → `MRS_FORBIDDEN`; every G4 / G5 table → 0 rows. Front end: `portal.html#tx/<A's id>` as B renders only the not-found message (jsdom, fake API that answers like RLS).

## 3. Role dashboards (step ٣)
One RPC per dashboard, each returning only what the role may see; KPI tiles (`card card-stat adm-tile`) + short lists (`adm-mini`), every tile linking to the filtered list / report.

### 3.1 `dash_ops(p_org uuid, p_filters jsonb DEFAULT '{}')` — keys `branch_id`
Gate `app.is_staff(p_org)` else `MRS_FORBIDDEN`. Rows: transactions with `has_branch_role(staff)`.
Returns:
- `transactions: {by_status:{<operational_status>: n}, open, stale_7d}` (`stale_7d` = open with `status_changed_at` older than 7 days);
- `appointments: {today:{requested, confirmed, completed, missed}, next_7d, upcoming:[≤10 {id, transaction_id, transaction_ref, container_no, appointment_at, status}]}` (cancelled / rescheduled excluded);
- `transport: {by_status:{planned, dispatched, loaded, delivered}, today_planned, late}` (`late` = `planned_at < now()` and status `planned|dispatched`), `upcoming:[≤10 {id, transaction_ref, container_no, leg_no, carrier_name, planned_at, status}]` — **no cost / sell**;
- `containers: {by_operational_state:{…}, open_returns, evidence_submitted, disputed, overdue, due_3d, due_7d, nearest:[≤10 {id, container_no, transaction_id, transaction_ref, return_deadline, return_status, days_left}]}` (open returns = `pending, evidence_submitted, disputed`);
- `alerts: {critical, warning, info}` (open + acknowledged), `exceptions_open`;
- `requests: {new, under_review}` only when the caller has an ops-writer role in the org, else `null`;
- `generated_at`.

### 3.2 `dash_finance(p_org uuid, p_filters jsonb DEFAULT '{}')` — keys `branch_id, currency`
Gate `app.fin_org_read(p_org)`. Rows with `has_branch_role(fin_read)` at the row's branch (supplier invoices by their own `branch_id`, everything else by the parent transaction's).
Returns (money always `by_currency`):
- `supplier_invoices: {by_status:{received, under_review, approved, disputed}, needs_review}`;
- `payables: {by_currency:{CUR:{open_amount, overdue_amount, open_count, overdue_count}}, due_7d_count}` — open = approved invoices with `payment_status IN ('unpaid','partial')`, `open_amount = app.fin_invoice_payable(si) − company_paid_amount − client_paid_amount` (≥ 0; the G4 payable = total − approved credit notes, same as G4 `due_approved_unpaid`), overdue = `due_date < today`;
- `costs: {review_queue, accruals_open, adjustments_pending}` (counts, same predicates as G4 `cost_review_queue` / `list_accruals` / `list_cost_adjustments` defaults);
- `billing: {intents_by_status:{open, draft, issued}, sync:{pending, in_flight, unknown, conflict, error}, jobs:{queued, failed, dead}, review_open, connection:{status, mode, sync_enabled}}`;
- `official: {by_currency:{CUR:{issued_count, total, paid, outstanding}}}` — **issued intents only, Daftra-synced fields only** (`remote_total`, `paid_amount`; `outstanding = remote_total − coalesce(paid_amount,0)`), `source:'daftra'`, `last_synced_at` (max); an issued intent with an **open G5 `issued_cancelled` review item** (Daftra cancelled it; the portal shows it cancelled) is left out and reported in `official.cancelled_pending_review.by_currency.CUR = {count, total}` (review fix);
- `unofficial: {open_intents, open_lines_total_by_currency}` labelled «قيد الإعداد — غير رسمي» (Marsa `lines_total` of `open|draft` intents; never added to `official`);
- `financial_status: {<financial_status>: n}` of the scoped transactions;
- `generated_at`.

### 3.3 `dash_management(p_org uuid, p_filters jsonb DEFAULT '{}')` — keys `branch_id, from, to` (default: current month, Riyadh; one bound alone → the other defaults to that bound's month)

- `period: {from, to}`; `requests: {received, converted, rejected}` in the period;

- `finance` — built only from rows where the caller also has fin_read (all mgmt roles have it today; still checked): `{official_by_currency:{CUR:{issued_count, total, paid}}, payables_overdue_by_currency:{CUR: amount}, margin_link:'#margins'}` (no margin computation here: the G4 analytical report is linked, not duplicated);

## 4. Advanced search (step ٤)
### 4.1 `search_records(p_org uuid, p_filters jsonb DEFAULT '{}')` → jsonb
Gate `app.is_staff(p_org)`; clients → `MRS_FORBIDDEN`.
**Filter keys** (`app.only_keys`): `q, declaration_no, bl_number, container_no, client_id, client_q, carrier_id, carrier_q, port, date_field, from, to, branch_id, operational_status, sort, limit, offset`.
- `q` (≥ 2 chars after trim, else `MRS_INVALID 'search_query_short'`): matches tx `ref`, `bl_number`, `declaration_no`, any `customs_declarations.declaration_no` (any status), any linked `bills_of_lading.bl_number`, any `containers.container_no`, client `name_ar / name_en / cr_number / vat_number`.
- `declaration_no`, `bl_number`, `container_no`: normalized (`upper`, western digits, whitespace removed; `container_no` — and the container branch of `q` — also strips `-`, as the G3 trigger stores it: `app.rpt_norm_container`), **contains** match on the tx column and the child tables above. Free text compared with CR / VAT / names also matches with Arabic-Indic digits turned western.
- `client_id` (uuid, exact) / `client_q` (name ar / en, CR, VAT contains).
- `carrier_id` (party uuid): tx has a trip with that `carrier_id` or a linked B/L with that `shipping_agent_id`; `carrier_q`: `transactions.shipping_line`, `bills_of_lading.carrier_name`, trip carrier party `name_ar / name_en` contains.
- `port`: `port_of_loading` / `port_of_discharge` of the tx or of a linked B/L contains.
- `date_field ∈ ('created','eta','declaration','status_changed')` (default `created`) + `from` / `to` (Riyadh dates); `declaration` = `transactions.declaration_date` or any non-cancelled `customs_declarations.declaration_date`.
- `branch_id` (must be a branch of `p_org`, else `MRS_INVALID 'branch_id'`; a branch outside the caller's scope just yields 0 rows); `operational_status`: one code or an array of codes (`app.is_code('operational_status', …)`).
- `sort ∈ ('created_desc' default, 'created_asc', 'ref', 'eta', 'status_changed_desc')`, always tie-broken by `id`.
- No filter at all → the most recent transactions (allowed: it is the same as the transactions list).
**Result:** `{items:[{id, ref, branch_id, branch_name, client_id, client_name, client_name_en, operation, mode, operational_status, bl_number, declaration_no, port_of_loading, port_of_discharge, shipping_line, eta, created_at, status_changed_at, container_count, financial_status|null, matched:[{field, value}] (≤ 5)}], total, limit, offset, fingerprint}`.
`matched` names the child values that hit (`container_no`, `declaration_no` + `declaration_status`, `bl_number`, `client`, `carrier`, `port`) — only values of rows the caller can read. `container_count` = real count of the tx's containers.
**Shared matcher:** the WHERE logic lives in one helper `app.rpt_tx_match(p_org uuid, f jsonb) RETURNS SETOF uuid` (STABLE, definer, revoked) used by both `search_records` and `report_transactions`, so a search export equals the transactions report for the same filters.

### 5.3 Export contract (binding)
1. **Same RPC, same filters.** The export calls the same reader with the exact filter object behind the visible table (a deep copy taken when the user presses the button), paging with `limit=500` (`margin_report`: 200) until `total`. No other endpoint, no service role, no extra column: the file columns = the visible table columns (+ hidden-by-width columns are not added).
2. **Totals match.** The file's totals row is built from the server `totals` of the first page; the exporter also recomputes every money / count total from the fetched rows in **integer minor units** (`Math.round(v*100)`) and refuses the file (`MRS_EXPORT 'totals_mismatch'`, shown as «تغيّرت البيانات أثناء التصدير، أعد المحاولة») when they differ, when `total` changes between pages, or when `fingerprint` changes (retry once first, G6a-13). For `margin_report` the check is Σ items per currency = `totals_by_currency`.
3. **Fingerprint** = `md5(string_agg(id::text || ':' || coalesce(updated_at::text,''), ',' ORDER BY id))` over the whole filtered set (trips / containers / tx rows).
4. **Caps** G6a-8; the count is known from page 1 (`total`) before anything else is fetched.
5. **Audit first.** After rows are fetched and checked, `MarsaApi.logReportExport({report, format, filters, row_count})`; only on success is the file built / downloaded / printed (G6a-9). Failure → error toast, no file.
6. **Excel (`assets/js/rpt/xlsx.js`, `window.MarsaXlsx`)**: `MarsaXlsx.build({title, sheets:[{name, rtl:true, columns:[{key, label, type:'text'|'int'|'money'|'number'|'date'|'datetime', width?}], rows:[{…}], totals:{…}|null}], meta:[[label, value]…]}) → Uint8Array` and `MarsaXlsx.blob(spec) → Blob`. Minimal OOXML: `[Content_Types].xml`, `_rels/.rels`, `docProps/core.xml`, `docProps/app.xml`, `xl/workbook.xml`, `xl/_rels/workbook.xml.rels`, `xl/styles.xml`, one `xl/worksheets/sheetN.xml` per sheet; ZIP **stored** (method 0) with CRC-32 and UTF-8 names (flag bit 11); `<sheetView rightToLeft="1">`, frozen header row, header style bold; numbers as `<c><v>` (no `t`), `money` numFmt `#,##0.00`, `int` `#,##0`, `date` custom `yyyy-mm-dd`, `datetime` `yyyy-mm-dd hh:mm` as Excel serials in **Asia/Riyadh** wall time; text as `inlineStr` (never evaluated as a formula); invalid XML chars stripped; sheet names ≤ 31 chars, `[]:*?/\` removed. A second sheet «معايير التقرير» / "Report criteria": report name, org, filters (human labels), generated at (Riyadh), generated by, row count. Totals row in bold at the bottom of the data sheet. Self-contained (does **not** modify `assets/js/xlsx-lite.js`; tests read the file back with `XlsxLite.read`).
7. **CSV**: `export.js` `toCsv(columns, rows, totals)` — RFC 4180, `\r\n`, UTF-8 **BOM**, numbers unformatted with `.` decimal, text cells starting with `= + - @ \t \r` prefixed with `'` (CSV formula-injection guard), totals as the last row.
8. **Print / PDF**: `export.js` renders a detached `<section class="rpt-print" dir="rtl">` (title, org, criteria list, generated at / by, the full table with `<thead>` repeated per page, totals `<tfoot>`), appends it to `body`, sets `body.rpt-printing`, calls `window.print()`, removes it on `afterprint` (and after 60 s as a fallback). `assets/css/pages/rpt.css` `@media print`: hide everything under `body.rpt-printing` except `.rpt-print`, A4 landscape `@page { size: A4 landscape; margin: 12mm }`, Cairo font, `font-variant-numeric: tabular-nums`, LTR cells for refs / numbers, `break-inside: avoid` on rows, no colors needed for meaning.
9. File names: `marsa-<report>-<YYYYMMDD-HHmm>.<xlsx|csv>` (ASCII only; no client / filter text in the name). Download via `Blob` + `URL.createObjectURL` + `a[download]`, URL revoked after click.
