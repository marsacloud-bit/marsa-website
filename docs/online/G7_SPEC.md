Read first: `docs/online/ARCHITECTURE.md`, then `G6B_SPEC.md`, `G6A_SPEC.md`, `G5_SPEC.md`, `G4_SPEC.md`, `G3_SPEC.md` (each with its "As built"), `G6B_REPORT_AR.md` §3–5, `BACKUP_RESTORE_AR.md`, `ENVIRONMENTS_AR.md` §4. Staging only, branch `online-staging`, base commit `566e952` (G6b).

Everything else is automated proof suites on PGlite, generated result tables, and documents. **G7 builds on G2–G6b and changes none of them**: no column added to an existing table, no existing function or policy re-created, no existing test expectation weakened (the only edits to old suites are the catalog lists in `rls-tests.js` that must name the new tables / RPCs, §Tests).

## Owner-control rules (binding)
- **Nothing is ever marked done on the owner's behalf.** Every step has three possible parts: **AUTO** (a suite on PGlite proves it now), **DOC** (a document deliverable written now), **OWNER** (needs the owner, real people or real services). An OWNER part is recorded as `قيد انتظار المالك (OWNER-PENDING)` with its exact procedure, in every document, report row and UI text. Wording like «تم» / «اكتمل» / «approved» / «passed» is forbidden for an OWNER part until the owner signs it in writing (the sign-off block in `G7_ACCEPTANCE_AR.md`).
- **No network, no real Supabase / Daftra / mailbox / WhatsApp / LLM / payment provider, no key, no secret** in code, tests, fixtures or docs. All suites run on PGlite with the existing mocks (`supabase/functions/daftra-sync/mock-adapter.js`, `supabase/functions/inbox-sync/mock-*.js`, `ai-mock.js`). Every new suite installs the same `globalThis.fetch` trap as `g6b-cycle-tests.js` (any call = FAIL).
- **No production data, no Blue Sea (البحر الأزرق) real data** anywhere. Pilot data = training / synthetic, or owner-authorized under the written plan of `G7_PILOT_PLAN_AR.md` (plan note «لا تُنقل بيانات الإنتاج بلا خطة وموافقة»).
- **Numbers are never invented.** Result tables (`G7_AI_EVAL_RESULTS.md`, `G7_PERF_RESULTS.md`, `G7_E2E_EVIDENCE.md`) are written by the suites themselves. Readiness / acceptance documents reference those files and suite names; where a number is not yet produced they say «يُملأ من تشغيل فعلي» and the integration step fills it from a real run. Cost figures are **formulas with placeholders**, each marked «تقدير — يُتحقق من الأسعار الرسمية».
- **Commercial billing (subscription invoices via Daftra, online payment) is deferred** (plan step ١١ note «الدفع الإلكتروني يمكن تأجيله إلى ما قبل البيع»). Plans carry an optional price placeholder only.
- No git commit / branch / stash / reset by any agent.

## Binding rules (apply to every item below)
- One migration: `supabase/migrations/20261108000100_g7_subscriptions.sql`. Preflight (read-only `DO` block) requires `schema_versions` row `20261107000100` (G6b) else `RAISE EXCEPTION 'G7 preflight: apply G6b first (schema_versions lacks 20261107000100 g6b_inbox)'` and creates nothing. Then `INSERT INTO public.schema_versions (version, name) VALUES ('20261108000100', 'g7_subscriptions') ON CONFLICT DO NOTHING`. Starts with `SELECT set_config('lock_timeout', '5s', true);`. Re-runnable (IF NOT EXISTS / OR REPLACE / DROP TRIGGER IF EXISTS / ON CONFLICT DO NOTHING for seeds — a re-run never overwrites owner edits of plans). Applies on the LIVE staging DB holding G2–G6b data (backfill is idempotent recount, §Data model 6).
- Every `SECURITY DEFINER` function (public RPC **and** app trigger / helper): `SET search_path = ''`, fully-qualified names, auth check first (`IF auth.uid() IS NULL THEN PERFORM app.fail('MRS_AUTH_REQUIRED'); END IF;` for RPCs), then role check (`app.is_platform_admin()` → else `MRS_FORBIDDEN`; org RPC → `app.has_role(p_org, ARRAY['admin'])` → else `MRS_NOT_FOUND`), errors only via `app.fail('MRS_*', detail)`, `REVOKE ALL ON FUNCTION … FROM PUBLIC, anon, authenticated` then `GRANT EXECUTE … TO authenticated` (RPCs only; app helpers / trigger functions get no grant).
- **RLS enabled on every new table; no policy; no grant to anon / authenticated** (all four new tables are "no-API" tables read through RPCs only, like `schema_versions`). No DELETE path anywhere.
- Audit: `app.tg_audit` (`trg_audit`) on `plans` and `org_subscriptions`. `subscription_events` is append-only (the existing append-only trigger pattern: `BEFORE UPDATE OR DELETE` + `BEFORE TRUNCATE` → `MRS_APPEND_ONLY`). `org_usage_counters` is a derived cache (not audited; reconciled by recount).
- **Plan-limit enforcement is server-side only** (triggers on the main create paths, §Data model 5). The UI may show usage but never decides. Errors: `MRS_PLAN_LIMIT` (detail = metric key) and `MRS_PLAN_INACTIVE` (detail = `trial_expired` | `suspended` | `cancelled`).
- **Inert by default:** every existing org gets plan `pilot` (all limits NULL = unlimited), status `active`. With that default every pre-G7 suite must keep its baseline unchanged (§Tests "regression gate").
- Trigger functions are named `app.g7_*`, triggers `trg_g7_*`; they never change the inserted row (one review-fix exception: `trg_g7_created_at` forces an API caller's `transactions.created_at` to `now()`) and never write tenant tables — only `org_usage_counters`.
- Front end: classic scripts, `node --check` clean; all text ar + en via `MarsaI18n`; DOM via `createElement` / `textContent` only (no `innerHTML` with data, no `insertAdjacentHTML`, no `eval`); original marketing-layout design (`page-hero`, `.card`, `adm-tile`, `table.table.table-striped.adm-table` inside `.table-wrap`, `badge badge-*`, `btn`, `form-control`, `dialog.adm-dialog`).
- Suites follow the existing harness conventions exactly (§Tests "harness").

## Data model (migration `20261108000100_g7_subscriptions.sql`)
Section order in the file: **P** preflight + schema_versions · **0** helpers · **1** tables · **2** seeds + backfill · **3** triggers · **4** platform / org RPCs · **5** RLS, audit, privileges.

### 1. `public.plans`
`code text PRIMARY KEY CHECK (code ~ '^[a-z][a-z0-9_]{1,30}$')`, `name_ar text NOT NULL (2..80)`, `name_en text (≤ 80)`, `sort int NOT NULL DEFAULT 100`, `is_active boolean NOT NULL DEFAULT true`, `max_users int`, `max_branches int`, `max_tx_month int`, `max_storage_mb bigint`, `max_messages_month int`, `max_ai_runs_month int` (each NULL = unlimited, CHECK ≥ 0), `price_monthly_sar numeric(12,2) CHECK (≥ 0)` (NULL = not priced), `notes text (≤ 2000)`, `created_at`, `updated_at`, `updated_by uuid`.
Seeds (G7-13) `INSERT … ON CONFLICT (code) DO NOTHING`.

### 2. `public.org_subscriptions` (one per org)
`org_id uuid PRIMARY KEY REFERENCES organizations(id) ON DELETE RESTRICT`, `plan_code text NOT NULL REFERENCES plans(code)`, `status text NOT NULL CHECK (status IN ('trial','active','suspended','cancelled'))`, `period_start date NOT NULL`, `period_end date CHECK (period_end IS NULL OR period_end >= period_start)`, `CHECK (status <> 'trial' OR period_end IS NOT NULL)`, `limit_overrides jsonb NOT NULL DEFAULT '{}'` (`CHECK (app.g7_overrides_valid(limit_overrides))`: object, keys ⊆ the six metric keys, values non-negative integers ≤ 10^9), `status_reason text (≤ 2000)`, `suspended_at timestamptz`, `suspended_by uuid`, `created_at`, `updated_at`, `updated_by uuid`.

### 3. `public.subscription_events` (append-only)
`id uuid PK`, `org_id uuid NOT NULL REFERENCES organizations(id)`, `at timestamptz NOT NULL DEFAULT clock_timestamp()`, `actor uuid` (NULL = migration / system), `action text CHECK (action IN ('created','plan_changed','limits_changed','period_changed','status_changed','suspended','activated','cancelled','recounted'))`, `from_plan text`, `to_plan text`, `from_status text`, `to_status text`, `reason text (≤ 2000)`, `detail jsonb NOT NULL DEFAULT '{}'` (counts / limits only). Index `(org_id, at DESC)`.

### 4. `public.org_usage_counters` (derived cache)
`org_id uuid REFERENCES organizations(id)`, `metric text CHECK (metric IN ('transactions_month','messages_month','ai_runs_month','storage_bytes'))`, `period_start date NOT NULL` (`'1970-01-01'` for the cumulative `storage_bytes`), `value bigint NOT NULL DEFAULT 0 CHECK (value >= 0)`, `updated_at`; `PRIMARY KEY (org_id, metric, period_start)`.
`users` and `branches` are **live gauges** (counted on demand with existing indexes), not cached.

### Metric keys (used in limits, overrides, usage JSON and `MRS_PLAN_LIMIT` detail)
| key | plan column | measured as |
|---|---|---|
| `users` | `max_users` | live, G7-3 |
| `branches` | `max_branches` | live: `branches.is_active` |
| `transactions_month` | `max_tx_month` | counter, `transactions` inserts |
| `storage_mb` | `max_storage_mb` | counter `storage_bytes` / 1 048 576 (ceil) |
| `messages_month` | `max_messages_month` | counter, `msg_messages` inserts |
| `ai_runs_month` | `max_ai_runs_month` | counter, `msg_ai_runs` inserts |

### 0. Helpers (`app`, SECURITY DEFINER where they read the new tables, no grants)
- `app.g7_period(ts timestamptz DEFAULT now()) → date` (IMMUTABLE-safe variant takes the ts).
- `app.g7_overrides_valid(jsonb) → boolean` (IMMUTABLE).
- `app.g7_limits(p_org uuid) → jsonb` effective limits `{users, branches, transactions_month, storage_mb, messages_month, ai_runs_month}` = override if present else plan column (JSON null = unlimited). Org without a subscription row ⇒ pilot (all null).
- `app.g7_usage(p_org uuid) → jsonb` `{users, branches, transactions_month, storage_mb, messages_month, ai_runs_month, over_limit: [keys]}` for the current period.
- `app.g7_assert_active(p_org uuid)` → `MRS_PLAN_INACTIVE` with detail `trial_expired` (status `trial` and `app.g7_period`-local date > `period_end`), `suspended`, `cancelled`; no row / `active` / unexpired `trial` pass.
- `app.g7_bump(p_org uuid, p_metric text, p_n bigint, p_enforce boolean) → bigint`: `INSERT … ON CONFLICT (org_id, metric, period_start) DO UPDATE SET value = value + EXCLUDED.value RETURNING value`; when `p_enforce` and the limit is not null and the new value exceeds it → `app.fail('MRS_PLAN_LIMIT', metric)` (the raise rolls the bump back with the statement; the row lock serializes concurrent creates, so two creates at `limit − 1` cannot both pass).
- `app.g7_check(p_org uuid, p_metric text)` for "at limit" checks without a bump (users, branches, outbound, drafts): `used + app.g7_pending(org, metric) >= limit` → `MRS_PLAN_LIMIT` (pending = in-flight sends / unfinished drafts; 0 for the other metrics — review fix).
- Review fix (recount race): `app.g7_bump` takes a shared per-org advisory lock; `app.g7_recount` / `platform_recount_usage` take it exclusively in a first statement.
- `app.g7_recount(p_org uuid) → jsonb`: **sets** (not adds) the current-month counters and `storage_bytes` from the real rows (idempotent); returns the usage.

### 5. Triggers on existing tables (new, `trg_g7_*`; enforcement = **E**, count only = **C**)
| table | timing / event | does |
|---|---|---|
| `organizations` | AFTER INSERT | create `org_subscriptions` (pilot, active) + event `created` |
| `organizations` | BEFORE UPDATE OF is_active | G7-14 re-activation guard |
| `transactions` | BEFORE INSERT | **E** `g7_assert_active` + `g7_bump('transactions_month', 1, true)` (covers `convert_request_to_transaction`, `import_commit`, direct staff insert) |
| `transactions` | BEFORE INSERT (`trg_g7_created_at`, INVOKER; review fix) | an API caller's `created_at` := `now()` (no back- / forward-dated insert can pick another month's counter); SQL / service-role imports keep their date |
| `branches` | BEFORE INSERT, BEFORE UPDATE OF is_active (false→true) | **E** active + `g7_check('branches')`; on a reactivation also `users`: used + (members of that branch counted nowhere else) ≤ limit (review fix) |
| `memberships` | BEFORE INSERT, BEFORE UPDATE OF is_active, role (→ active staff) | **E** active + `g7_check('users')` unless the user is already counted (covers `admin_add_member`, `accept_invitation`, reactivation) |
| `invitations` | BEFORE INSERT (role ≠ client) | **E** active + `g7_check('users')` |
| `documents` | BEFORE INSERT | **E** active + `g7_bump('storage_bytes', size_bytes, true)` (limit compared in bytes) |
| `finance_documents` | BEFORE INSERT | same |
| `msg_attachments` | AFTER INSERT | **C** `g7_bump('storage_bytes', size_bytes, false)` |
| `msg_messages` | AFTER INSERT | **C** `g7_bump('messages_month', 1, false)` |
| `msg_outbound` | BEFORE INSERT, BEFORE UPDATE OF state (failed → queued, `retry_msg_send`) | **E** active + `g7_check('messages_month')`, counting sends still in flight (`app.g7_pending`, review fix) |
| `msg_ai_runs` | AFTER INSERT | **C** `g7_bump('ai_runs_month', 1, false)` |
| `msg_jobs` | BEFORE INSERT WHEN (NEW.kind = 'draft') | **E** active + `g7_check('ai_runs_month')`, counting unfinished draft jobs (`app.g7_pending`, review fix) |
| `storage.objects` | AFTER INSERT OR UPDATE OF metadata (`trg_g7_object_size`, review fix) | buckets documents / finance: `metadata.size` must equal the registered row's `size_bytes` (`MRS_INVALID 'size_bytes'`); recount uses the real object size |
Client-originated rows (`submit_service_request`, client document upload) are **not** refused by an expired trial except where they create a counted row (documents: yes, as storage). Service-role ingest is never refused (G7-4/5/6).

### 6. Backfill (idempotent)
Insert a `pilot` / `active` subscription for every org lacking one (`ON CONFLICT DO NOTHING`; event `created` only for rows actually inserted), then `PERFORM app.g7_recount(id)` for every org. A re-run changes no count (proven by test).
