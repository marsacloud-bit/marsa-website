# قوالب استيراد البيانات القديمة — مرسى (G7، الخطوة ١٠)

> **الحالة:** قوالب ودراسة فقط. **لا يوجد في G7 أي مسار استيراد جديد** (لا RPC لاستيراد العملاء أو المعاملات أو الحاويات مباشرة). الترحيل اختياري، وأي تجربة استيراد تجري في **مؤسسة تجريبية (sandbox) على Staging فقط وبعد موافقة المالك المكتوبة** — انظر [`../online/G7_MIGRATION_STUDY_AR.md`](../online/G7_MIGRATION_STUDY_AR.md).
> كل الصفوف في الملفات أمثلة **وهمية** (بريد `@example.com`، أرقام تجريبية). احذفها قبل تعبئة بيانات حقيقية، ولا تُرسل ملفًا معبّأً ببيانات حقيقية عبر بريد أو دردشة.

## الملفات

| الملف | المحتوى | كيف يُستورد اليوم |
|---|---|---|
| `clients.csv` / `clients.xlsx` | ملفات العملاء (السجل الرئيسي) | **لا مسار استيراد مباشر.** يُنشأ العميل يدويًا من «العملاء ← عميل جديد» في لوحة الموظفين، أو عند تحويل طلب إلى معاملة (اختيار عميل موجود أو إنشاء ملف جديد بعد مراجعة «عملاء مطابقون محتملون»). القالب أداة جرد ومطابقة قبل القرار. |
| `transactions.csv` / `transactions.xlsx` | الشحنات / المعاملات | **الرفع الجماعي** (`bulk-upload.html`، نوع البيانات «شحنات»): كل صف يصبح **طلب خدمة** (`source = bulk`) عبر `import_commit`، ثم يراجعه الموظف ويحوّله إلى معاملة من «الطلبات الواردة ← تحويل إلى معاملة». لا تُنشأ معاملة مباشرة من الملف. |
| `containers.csv` / `containers.xlsx` | حاويات المعاملات القديمة | **لا مسار استيراد مباشر.** أرقام الحاويات تدخل مع الشحنة في عمود «أرقام الحاويات» من قالب المعاملات، أو يدويًا من صفحة المعاملة («إضافة حاوية»). القالب للجرد والمطابقة وتقدير حجم العمل. |

كل ملف `.xlsx` فيه ورقتان: ورقة البيانات، وورقة «شرح الأعمدة» (العمود، الصيغة، الإلزام، مثال). ملفات CSV بترميز UTF-8 مع BOM (تُفتح في Excel بالعربية مباشرة)، الفاصل `,`. الملفات وُلّدت بسكربت خارج المستودع يستخدم `assets/js/xlsx-lite.js` (`writeBytes`).

## 1) `clients` — العملاء
الأعمدة بالترتيب (الأسماء المشتركة مع الرفع الجماعي مكتوبة بنفس تسميته):

| العمود | يقابل في مرسى | النوع / الصيغة | إلزامي |
|---|---|---|---|
| اسم العميل | `clients.name_ar` | نص 2–160 حرفًا | نعم |
| الاسم بالإنجليزية | `clients.name_en` | نص ≤ 160 | لا |
| نوع العميل | `clients.client_type` | «فرد» أو «منشأة» | نعم |
| السجل التجاري | `clients.cr_number` | 10 أرقام بالضبط | لا |
| الرقم الضريبي | `clients.vat_number` | 15 رقمًا (السعودي يبدأ وينتهي بـ 3) | لا |
| رقم الجوال | `clients.phone` | `05xxxxxxxx` (10 أرقام تبدأ بصفر) | لا |
| البريد الإلكتروني | `clients.email` | بريد صحيح ≤ 160 | لا |
| الشخص المسؤول | `clients.contact_person` | نص ≤ 120 | لا |
| التواصل المفضل | `clients.preferred_contact` | «جوال» أو «واتساب» أو «بريد» | لا |
| العنوان المختصر | `clients.national_address_short` | 4 أحرف إنجليزية كبيرة + 4 أرقام، مثل `RRRD2929` | لا |
| المدينة | `clients.national_address.city` | نص | لا |
| ملاحظات | `clients.notes` | نص ≤ 2000 | لا |
| المرجع القديم | (لا يقابله عمود؛ للمطابقة فقط) | رقم العميل في النظام السابق | نعم |

قيود الخادم التي تفرض الصيغة: `cr_number ~ '^[0-9]{10}$'`، `vat_number ~ '^[0-9]{15}$'`، `phone ~ '^0[0-9]{9}$'`، `national_address_short ~ '^[A-Z]{4}[0-9]{4}$'`. لا يُكرَّر العميل: المطابقة بالرقم الضريبي ثم السجل التجاري ثم الاسم بعد التوحيد (انظر دراسة الترحيل §3).

## 2) `transactions` — المعاملات (عبر الرفع الجماعي)
**عناوين الأعمدة هي نفسها تسميات حقول «شحنات» في `assets/js/bulk-upload.js` وبالترتيب نفسه**، لذلك تُطابَق تلقائيًا في خطوة «مطابقة الأعمدة» دون تعديل:

| # | العمود | النوع / الصيغة | إلزامي في الرفع الجماعي |
|---|---|---|---|
| 1 | اسم العميل | نص | نعم |
| 2 | الشركة | نص | لا |
| 3 | نوع العميل | «فرد» أو «منشأة» | لا |
| 4 | رقم الجوال | `05xxxxxxxx` أو `+9665xxxxxxxx` | نعم |
| 5 | البريد الإلكتروني | بريد صحيح | لا |
| 6 | السجل التجاري | 10 أرقام (تحذير إن خالف) | لا |
| 7 | الرقم الضريبي | 15 رقمًا (تحذير إن خالف) | لا |
| 8 | نوع العملية | «استيراد» أو «تصدير» | نعم |
| 9 | الخدمة | اسم خدمة من قائمة الموقع، وإلا تُعتمد «تخليص جمركي متكامل» (أو «تخليص صادرات» للتصدير) | لا |
| 10 | وسيلة الشحن | «بحري» أو «جوي» أو «بري» | نعم |
| 11 | بلد المنشأ | نص | لا |
| 12 | منفذ الوصول | منفذ سعودي من قائمة الموقع، مثل «ميناء جدة الإسلامي» | نعم |
| 13 | وصف البضاعة | نص ≥ 3 أحرف | نعم |
| 14 | رمز HS | 4–12 رقمًا | لا |
| 15 | القيمة | رقم أكبر من صفر | نعم |
| 16 | العملة | USD أو EUR أو CNY أو AED أو SAR | نعم |
| 17 | الوزن (كجم) | رقم أكبر من صفر | لا |
| 18 | عدد الحاويات | عدد صحيح أكبر من صفر | لا |
| 19 | نوع الحاوية | 20 قدم أو 40 قدم أو LCL (للبحري) | لا |
| 20 | أرقام الحاويات | ISO 6346 (4 أحرف + 7 أرقام)، مفصولة بفواصل | لا |
| 21 | رقم البوليصة | نص ≤ 40 | لا |
| 22 | الخط الملاحي | نص | لا |
| 23 | رقم البيان الجمركي | أرقام، للاستيراد فقط (يُتجاهل مع التصدير) | لا |

ملاحظات:
- **لا يوجد عمود «المرجع القديم» في هذا القالب** حتى تبقى كل العناوين مقبولة في الرفع الجماعي. المطابقة مع النظام القديم تتم بملف «المراجع» الذي يتيحه الرفع الجماعي بعد الاعتماد (`marsa-refs-<batch>.csv`: رقم الصف ← رقم الطلب) مع جدول مطابقة يحتفظ به فريق الترحيل (رقم الصف ← المرجع القديم).
- كل صف يحمل معرّف مصدر فريد (بصمة الملف + الورقة + رقم الصف)؛ رفع الملف نفسه مرة ثانية يُرفض كتكرار. رقم بوليصة معروف مسبقًا في طلب أو معاملة يجعل الصف «مكررًا» ينتظر قرارًا بشريًا.
- **المعاملة القديمة المنتهية لا تعود «منتهية» تلقائيًا**: الطلب يُحوَّل إلى معاملة بمرحلة «جديدة» ثم تُنقل مراحلها يدويًا (وتنطبق قواعد المستندات). لذلك ينصح بترحيل **المعاملات المفتوحة فقط** (دراسة الترحيل §6).
- حدود الرفع الجماعي اليوم: ملف واحد = دفعة واحدة، وعدد صفوف محدود لكل ملف (رسالة «قسّمه إلى ملفات أصغر»).

## 3) `containers` — الحاويات
| العمود | يقابل في مرسى | النوع / الصيغة | إلزامي |
|---|---|---|---|
| المرجع القديم للمعاملة | (مطابقة فقط) | رقم المعاملة في النظام السابق | نعم |
| رقم البوليصة | `bills_of_lading.bl_number` / `containers.bl_id` | نص ≤ 40 | لا |
| رقم الحاوية | `containers.container_no` | `^[A-Z]{4}[0-9]{7}$` بخانة تحقق ISO 6346 صحيحة | نعم |
| نوع الحاوية | `containers.container_type` | `20ft`، `40ft`، `40hc`، `45ft`، `20rf`، `40rf`، `LCL`، `other` | لا |
| رقم الختم | `containers.seal_no` | نص | لا |
| الوزن (كجم) | `containers.gross_weight_kg` | رقم ≥ 0 | لا |
| تاريخ الخروج من الميناء | `containers.gate_out_at` | `YYYY-MM-DD` | لا |
| تاريخ التسليم | `containers.delivered_at` | `YYYY-MM-DD` | لا |
| آخر موعد للإرجاع | `containers.return_deadline` | `YYYY-MM-DD` (موعد وليس إثباتًا) | لا |
| موقع الإرجاع | `containers.return_location` | نص ≤ 120 | لا |
| حالة الإرجاع في النظام السابق | (للجرد فقط) | نص حر | لا |
| تاريخ الإرجاع الفعلي | (للجرد فقط) | `YYYY-MM-DD` | لا |
| ملاحظات | `containers.notes` | نص ≤ 1000 | لا |

**مهم:** في مرسى لا تصبح الحاوية «أُرجعت فارغة» إلا بإيصال استلام الفارغ المؤكَّد على المعاملة نفسها (أو إعفاء موثّق بسبب). حالة الإرجاع القديمة **لا تُنقل كإثبات**؛ تبقى للجرد، والحاوية المرحَّلة تبدأ «بانتظار الإرجاع» حتى يُرفع الإيصال ويُتحقق منه.

## 4) قواعد عامة
- التواريخ `YYYY-MM-DD` (توقيت الرياض). الأرقام بلا فواصل آلاف. الأرقام العربية-الهندية مقبولة في الرفع الجماعي لكن يُفضَّل اللاتينية.
- لا كلمات مرور ولا بيانات بطاقات ولا أرقام هوية كاملة في أي قالب (رقم هوية السائق يُحفظ آخر 4 أرقام فقط في مرسى).
- لا تُرحَّل الرسائل القديمة (بريد / واتساب) بلا موافقة موثقة؛ لا قالب لها.
- التحقق الآلي الوحيد في G7: اختبار `g7-e2e-tests.js` §0 يتحقق أن عناوين القوالب تطابق القوائم الموثقة هنا، وأن عناوين قالب المعاملات مقبولة كحقول «شحنات» في الرفع الجماعي.
