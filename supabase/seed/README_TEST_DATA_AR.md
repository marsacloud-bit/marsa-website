# بيانات تجريبية لمؤسسة «مرسى» (slug = `marsa`)

ملفان للصق في **Supabase → SQL Editor** (ليسا ترحيلات، ولا يضافان إلى `all_migrations.sql`):

| الملف | ماذا يفعل |
|---|---|
| `test_data_seed.sql` | يضيف بيانات وهمية كاملة لتجربة كل الشاشات |
| `test_data_cleanup.sql` | يحذف كل ما أضافه السكربت (وما أضفته أنت على العملاء/المعاملات التجريبية أثناء التجربة) ولا شيء غيره |

## التشغيل
1. افتح SQL Editor ← New query، والصق **الملف كاملًا**، ثم Run مرة واحدة. لا حاجة لـ BEGIN/COMMIT (المحرر ينفذه كمعاملة واحدة: أي خطأ = لا شيء يُكتب).
2. آخر نتيجة صف واحد بالأعداد (العملاء، المعاملات حسب الحالة، الحاويات، السدادات، الرحلات، حركات العهدة).
3. تشغيله مرة ثانية يُرفض برسالة واضحة ولا يغيّر شيئًا. ويُرفض أيضًا إذا كان في المؤسسة سائق اسمه يبدأ بـ «تجريبي — » أو جواله أحد الأرقام التجريبية `0500000101` … `0500000108` (بأي صيغة، مثل +966)، أو شاحنة لوحتها `TST…` — غيّرها من شاشة الأسطول أولًا.
4. للحذف: الصق `test_data_cleanup.sql` كاملًا ← Run. آخر نتيجة صف أعداد **كلها 0**. يفضل تشغيله في وقت هادئ (يقفل الجداول لحظيًا).

## ما الذي يُضاف
- 20 عميلًا أسماؤهم تبدأ بـ «تجريبي — »، أكواد دفترة `TST-1001` … `TST-1020`، فئات مطار/ميناء/مشترك، بلا بريد ولا جوال.
- 61 معاملة (2–4 لكل عميل) بكل الحالات: جديدة، قيد العمل، البيان (كل مراحل فسح)، الموعد، النقل، إرجاع الفارغ، منتهية تشغيليًا، قيد الفوترة، تمت الفوترة (يدويًا بدور المالية — بلا دفترة)، مغلقة، وواحدة ملغاة. بوالص `TESTBL…`، حاويات `TSTU…` بخانة تحقق صحيحة، Ro-Ro، جوي، إعادة تصدير، بيانات `TSTD…` بتاريخ هجري وميلادي.
- أسطول خاص بالسكربت: 8 سائقين «تجريبي — سائق …» (`0500000101` … `0500000108`) و6 شاحنات `TST1001` … `TST1006` تُنشأ كسجلات جديدة، فلا يُمسّ أي سائق أو شاحنة موجودة.
- مواعيد وحركات بهؤلاء السائقين والشاحنات، قيمة نقل وإيراد، أنواع جهة النقل (مورد/شركة/مباشر/غير محدد)، مواعيد فائتة وإرجاع متأخر لتظهر شارات المتابعة والحرجة.
- تواريخ متسقة لكل معاملة: الوصول المتوقع (ETA) مستقبلي للجديدة/قيد العمل وماضٍ من مرحلة البيان فما بعد، ثم تاريخ البيان، ثم التسليم، ثم الإرجاع، والسدادات بين تاريخ البيان واليوم. تاريخ الإنشاء يبقى وقت التشغيل الفعلي (عليه يُحسب عداد الاشتراك الشهري).
- شارات «متأخرة في المرحلة» تظهر فورًا: آخر تحديث لثلثي المعاملات التجريبية مُرجَّع للخلف (بعضها تنبيه وبعضها حرج حسب قواعد المؤسسة)، وبعض البيانات المفتوحة أقدم من 3 أيام (تنبيه «بيان متوقف»).
- نحو 80 سدادًا بكل الأنواع ومصادر التمويل وطرق الدفع وبنود الخدمة، وسداد مجمع واحد، وعهدة لـ 6 عملاء (إيداع/خصم/إرجاع).

## ملاحظات مهمة
- **كل السدادات «بانتظار المراجعة» أو «مسودة»**: الاعتماد يحتاج موظفًا غير المُنشئ (أربع أعين)، والسكربت يعمل باسم المدير فقط. اعتمدها بنفسك من مستخدم ثانٍ إن أردت.
- إرجاع الحاويات مسجّل كـ «إعفاء موثق» لأن إثبات الإرجاع الحقيقي يحتاج ملف EIR مرفوعًا.
- لا يُنشأ أي شيء في دفترة ولا أي بريد أو رسالة أو فاتورة أو طلب فوترة أو مستخدم.
- الحذف لا يرجع عدادات الأرقام (MRS-… / PAY-… / CUS-…): الأرقام الحقيقية التالية تكمل بعدها فقط. وإن رفعت ملفات على معاملات تجريبية فاحذفها من شاشة Storage (السكربت يطبع مساراتها).
- الحذف **يرفض** إذا وجد شيئًا يبدو حقيقيًا مرتبطًا بالبيانات التجريبية (معاملة حقيقية تستخدم طرفًا تجريبيًا، سائق أو شاحنة حقيقية تابعة لشركة نقل تجريبية، فاتورة مورد حقيقية لمورد تجريبي، بوليصة حقيقية لوكيل ملاحة تجريبي، سداد حقيقي لمستفيد تجريبي، علامة تجريبية على عميل حقيقي، أو رسائل/فوترة/دفترة مرتبطة) ويذكر الجدول والعمود دون حذف أي شيء.
- التعديل الوحيد على سجل حقيقي: سائق حقيقي «آخر شاحنة» له شاحنة تجريبية يُفرَّغ هذا الحقل فقط ويبقى السائق (يُذكر اسمه في رسالة NOTICE).
- السكربتان يوقفان مؤقتًا بعض المشغلات (triggers) داخل نفس المعاملة ويعيدانها كما كانت، لذلك شغّلهما في وقت هادئ.
